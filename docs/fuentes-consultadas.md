# Fuentes y límites — Rutitas Backend

1. **Paquete conjunto aportado:** `Proyecto Rutitas.zip` (fuente histórica no incluida en este paquete; no verificable aquí); Constitución candidata, AGENTS, memoria, documentos de arquitectura base y cinco definiciones de agentes/skills compartidas. Se derivó de estas fuentes el paquete autónomo de Backend.
2. **Instrucción del profesor comunicada por el usuario:** preparar `constitution.md`, `AGENTS.md`, `memoria.md`, subagentes, skills y `spec.md`, `plan.md`, `task.md` de arquitectura base para Backend y Móvil; sin funciones específicas y sin ejecutar tareas.
3. **Auditorías anteriores** mencionadas en el paquete: Fase 2, Fase 3, Fase 4 y Fase 4.1, más comparación histórica v1/v2. Contexto, no ratificaciones.
4. **Tecnologías observadas**: React/TypeScript/Vite/Capacitor en un prototipo candidato; .NET/Kotlin/AWS en ejemplos académicos. No se adoptan automáticamente.

No se dispone aquí del acuerdo humano que ratifique la arquitectura, seleccione stack, designe aprobadores o autorice implementación. Las transcripciones académicas pueden contener errores ASR.

## Comunicación posterior del equipo (2026-11-04)

- El usuario reportó que el profesor exige **base de datos NoSQL** y solo permite elegir hospedaje entre **Azure, AWS o Google Cloud**. Es una comunicación de segunda mano; falta la instrucción primaria fechada.
- El usuario manifestó la preferencia del equipo por **ASP.NET Core 10/C#** debido a sus herramientas, y por **Google Cloud** ante la intención de usar mapas. Estas son **preferencias**, no ratificaciones.
- Las propuestas de Cloud Run, Firestore, Firebase Authentication y los dos catálogos alternativos de siete endpoints son **análisis técnico del asistente**, registrados solo como exploración. Véase [el anexo tecnológico](propuestas-futuras/stack-backend-y-cloud.md).
